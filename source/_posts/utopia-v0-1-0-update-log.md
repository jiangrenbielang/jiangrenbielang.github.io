一个月前，{% post_link utopia-kaoyan-platform 乌托邦考研平台 %} 在这里诞生；用了一个月，我越来越清楚地感觉到：LibreTV 的形态和我要的不一样。它是为浏览器聚合搜索设计的，而我需要的是一个每天打开、看网课、自动记时长的「学习台」，并且我大部分时间在 Windows 桌面上。于是有了这次大重构。以下是 v0.1.0 的更新日志。

## 新增

- **TVBox 配置地址数据入口**：填一份接口 JSON，点播站点、解析线路、壁纸全带出来；一条地址完成导入，多仓库配置（`urls:[...]`）自动跟随。
- **分类浏览页**：按站点分类翻页找课。
- **播放页解析线路面板**：一条线路不行就换下一条。
- **Electron 桌面客户端（Windows x64）**：主进程拉起内建本地数据层（静态导出页面 + 编译好的服务核），监听 `127.0.0.1:3210`，不再有 Next.js 长驻服务；去掉应用菜单栏，`Ctrl+,` 打开设置、`F11` 全屏、`Ctrl+=/-/0` 缩放；渲染层日志转发到 `desktop.log`，错误页能展开技术细节，出问题不再靠猜。
- **壁纸系统**：三种来源可切换——跟随 TVBox 配置自带的壁纸、导入本地图片（存 IndexedDB，单张上限 12MB）、或关闭；压暗程度和填充方式（铺满裁切 / 完整留边）都可调。
- **玻璃化界面**：有壁纸时，卡片、输入框、顶栏变成半透明 + `backdrop-filter` 毛玻璃，壁纸透出来但文字始终落在稳定的颜色上。

## 重构与变更

- **服务端抽成宿主无关的服务核**（`src/server/`）：同一份逻辑，部署到 Web 时是 Next.js 的 Route Handler（`src/app/api/**` 只是薄壳），跑在桌面时是 Electron 主进程内建的 Node `http.Server`。改一处，两端同步生效，不会再出现「网页上好了、桌面端还是旧行为」的漂移。
- **界面整体换血**：LibreTV 的深蓝黑霓虹风改为 TVBox 风格——中性深色、海报网格、顶部分类 tab。学习计时、倒计时、统计图表、课程库这些乌托邦自己的东西全部保留。
- **壁纸模式下整套调色板强制切到深色玻璃 HUD**（白字 + 蓝强调色）：浅色主题下近黑文字压在偏暗照片上会糊成一片，零散改字色是补不完的；不管系统主题、不管壁纸明暗，对比度都稳定。关掉壁纸，界面原样回到实色。
- **敏感配置收紧**：网盘令牌、内网放行这类配置只留在主进程/服务端，页面拿不到。

## 移除

- **LibreTV 整套 Web 端配置**：访问密码、`.env` 环境变量、Docker 配置项。个人工具不需要这些。
- **iframe 嵌入播放**：iframe 是跨域页面，播放器读不到播放状态，计时只能按「页面可见时长」近似。现在统一走直链 + 解析线路，m3u8/mp4 直接播、按真实播放进度计时、能拖进度条也能记住看到哪，不再维护两套计时口径。
- **companion 伴生程序 + mpv 本地高清播放**：用户要装 Python 和 mpv、构建要 PyInstaller 打包、mpv 是独立窗口嵌不进页面、关闭后才同步学习记录——整套删掉。播放全部回到应用内的 ArtPlayer + hls.js，学习体验从「弹个窗口、关了才记时长」变成「就在学习台里看、看着就计时」。
- 安装包从 **160.5 MB 减到 116.8 MB**，构建不再需要 Python、mpv、companion 目录——任何人 clone 下来就能构建。

## 修复

- 播放器曾把**所有**地址硬编码按 m3u8 塞给 hls.js，mp4 直链永远播不出来。现在按地址类型分流 HLS / 原生播放。
- 代理给整个响应流挂了 8 秒超时，185MB 的网课播到第 8 秒必断、播放器反复重连，表现为「加载极慢」。现在只对等响应头限时。

## 说明与已知限制

- 依赖 Spider 引擎（jar/dex）的站点会被跳过并说明原因——那是 Android 原生生态，Web 客户端跑不了，宁可明确告知也不假装能用。
- 乌托邦现在是纯粹的**个人考研学习台**：数据全在本地，无账号，无广告。
